# JASTAR HUB

**Одна молодёжь. Единые возможности. Общие результаты.**

Единая цифровая платформа Молодёжных советов группы АО «Самрук-Қазына», портфельных компаний Фонда и их дочерних организаций. Профили молодых сотрудников, проекты и мероприятия советов, независимая экспертиза и открытые рейтинги, в которых баллы начисляются только за подтверждённые результаты.

> **Два режима.** На GitHub Pages сайт работает с общей базой Supabase: настоящие аккаунты, роли и данные для всех пользователей. При открытии `index.html` как локального файла включается демо-режим с тестовыми данными в браузере. Записи с пометкой «ТЕСТ» — вымышленные.

## Запуск

Откройте `index.html` в браузере — сервер и установка зависимостей не нужны.

Чтобы опубликовать через **GitHub Pages**: Settings → Pages → Source: *Deploy from a branch* → ветка `main`, папка `/ (root)`. Сайт будет доступен по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

## Как устроен доступ (общая база)

- Каждый регистрируется сам и получает роль «Участник». Председатель совета подтверждает членство.
- Роли назначает только главный администратор: «Администрирование → Пользователи и роли».
- Все изменения статусов, ролей и оценок выполняют серверные функции в базе (`supabase/migrations/002_rpc.sql`), которые проверяют права. Из браузера обойти их нельзя: прямые изменения таблиц запрещены правилами RLS.
- Тестовые данные загружает и удаляет администратор: «Администрирование → Данные».

### Первый запуск (один раз)

1. Supabase → Authentication → Sign In / Providers → Email: выключить **Confirm email** (встроенная почта Supabase отправляет письма только участникам команды проекта).
2. Зарегистрироваться на сайте и выполнить в Supabase → SQL Editor:
   `update public.profiles set role = 'admin' where id = (select id::text from auth.users where email = 'ваш@email');`
3. Включить GitHub Pages: Settings → Pages → Deploy from a branch → `main` / `(root)`.

## Демо-аккаунты (демо-режим)

В демо-режиме кнопка с названием роли в верхней панели переключает тестовые аккаунты:

| Роль | Что можно проверить |
|---|---|
| Главный администратор Фонда | Компании и ДЗО, пользователи и роли, назначение экспертов, веса методики, апелляции, журнал аудита |
| Председатель совета (KEGOC) | Профиль компании, состав совета, подтверждение участников, проекты, статистика компании |
| Региональный председатель (КТЖ, Караганда) | Мероприятия и проекты региона, региональная аналитика |
| Участник (QazaqGaz) | Профиль, достижения, проекты с командой из разных компаний, отправка на проверку |
| Независимый эксперт | Очередь проверки, оценка по 5 критериям, подтверждение, уточнения, отклонение |
| Эксперт из КазМунайГаза | Пример конфликта интересов: заявки группы КМГ ему не назначаются и не открываются |
| Гость | Открытые страницы, подтверждённые проекты, рейтинги и новости |

## Разделы

Главная (дашборд с картой регионов), обратная связь (предложения, рекомендации, вопросы, сообщения о проблемах, благодарности коллегам и советам, контакты платформы и председателей), компании и Молодёжные советы, участники, личный кабинет, проекты, календарь мероприятий, рейтинг советов, ТОП-100 молодых лидеров, кабинет независимого эксперта, новости и медиа, база знаний, аналитика для руководства (Excel и PDF, квартальный отчёт), сравнение компаний, администрирование, открытая методика рейтинга.

## Методика рейтинга (кратко)

**Молодёжные советы:** проекты и результативность 25%, охват и вовлечённость 20%, социальная деятельность 15%, профессиональное развитие 15%, межкорпоративное взаимодействие 10%, инновации 10%, информационная активность 5%.

**Молодые лидеры:** личный вклад в проекты 30%, организация и лидерство 20%, реализованные инициативы 20%, волонтёрство 10%, межкорпоративное взаимодействие 10%, профессиональное развитие и наставничество 10%.

- Учитываются только активности, подтверждённые независимым экспертом.
- Качество проекта = средняя оценка эксперта × (0,5 + 0,5 × выполнение KPI, не выше 120%).
- Нормирование по размеру: вовлечённость = 1 − e^(−охват / численность молодёжи); суммы по проектам делятся на √(численность / 100).
- Каждый показатель приводится к шкале 0–100 по лучшему результату периода.
- Личные баллы — только в пределах доли участника в команде (сумма долей = 100%).

Защита от завышения: проверка дублей, обязательные KPI и документ-доказательство, фото не влияют на баллы, подтверждённые значения не могут превышать заявленные, конфликт интересов экспертов, история рейтинга, апелляции, журнал аудита.

## Структура репозитория

```
index.html            собранное приложение (открывается напрямую)
build.py              сборка index.html из src/
src/
  01-data.js          справочники, оргструктура, генератор тестовых данных
  02-core.js          хранилище, роли (RBAC), расчёт рейтингов, проверка, аудит, API-слой
  03-ui.js            компоненты, графики, карта, маршрутизация, оболочка
  04-pages-a.js       главная, компании, участники, профили, вход и регистрация
  05-pages-b.js       проекты и мероприятия
  06-pages-c.js       рейтинги, экспертиза, новости, база знаний, аналитика, админка, методика
  07-main.js          обработчики событий и запуск
  styles.css          дизайн-токены и стили (светлая и тёмная темы, адаптивность)
  065-live.js         режим общей базы: вход, загрузка данных, вызовы серверных функций, файлы
  066-feedback.js     обратная связь, благодарности, контакты
supabase/migrations/  схема Supabase: 001 таблицы и RLS, 002 серверные функции, 003 справочники, 004 хранилище, 005 обратная связь
```

После изменения файлов в `src/` выполните `python3 build.py`.
